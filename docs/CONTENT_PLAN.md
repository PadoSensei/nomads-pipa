# Content Plan

**Project:** Nomads Pipa  
**File:** `docs/CONTENT_PLAN.md`
**Status:** Proposed  
**Primary audience:** Digital nomads, travellers, local residents, and partner businesses  
**Initial languages:** English, Brazilian Portuguese, and Spanish
**Platform:** Next.js, TypeScript, Tailwind CSS, shadcn/ui, Supabase

---

## 1. Purpose

This document defines the content strategy for Nomads Pipa.

The goal is to create a useful, trustworthy, and easy-to-maintain local discovery platform.

Content should help users answer practical questions:

- Where should I eat today?
- Where can I work remotely?
- What is happening tonight?
- Where can I meet other nomads?
- How can I get around Pipa?
- Where can I find accommodation?
- Which local services can help me?
- What experiences are worth discovering?

Nomads Pipa should provide curated, contextual information rather than attempting to reproduce every feature of a traditional map or search engine.

---

## 2. Content Principles

### 2.1 Useful before promotional

Every listing should provide useful information before promotional messaging.

### 2.2 Contextual discovery

Organise information around what users want to do, not just business classifications.

For example:

- Remote-work cafés.
- Affordable daily meals.
- Sunset spots.
- Live music tonight.
- Weekday nightlife.
- Vegan food.

### 2.3 Trust and accuracy

- Verify contact details before publishing.
- Do not invent opening hours.
- Confirm event dates.
- Clearly distinguish official events from third-party events.
- Identify sponsored or partner placements where appropriate.
- Review time-sensitive information regularly.

### 2.4 Mobile-first writing

Content should be easy to scan on a phone.

Use:

- Short paragraphs.
- Descriptive headings.
- Clear labels.
- Useful links.
- Concise calls to action.

# 7. Language Strategy

## 7.1 Supported languages

- English (`en`) — Default language for international nomads.
- Brazilian Portuguese (`pt-BR`) — Natural language for local residents, Brazilian visitors, and businesses.
- Spanish (`es`) — Broadly understandable Spanish for South American and international travellers.

## 7.2 Recommended approach

Use a hybrid translation workflow.

### Interface content

Store interface labels and messages in translation files.

Examples:

- Navigation.
- Buttons.
- Form labels.
- Error messages.
- Category names.
- Status labels.

### Editorial content

Store language versions in the database or shared content models.
In the TypeScript content models (`lib/content/`), listings and categories support an optional `translations` mapping (`Partial<Record<ContentLocale, ...>>`) that coordinates with NP-003:
- Base listings can define localized `name` and `description`.
- Event listings can define localized `title`, `description`, and `priceDescription`.
- Discovery categories can define localized `name`, `tagline`, `description`, and `highlightBadge`.
- The `getLocalizedListing`, `getLocalizedEvent`, and `getLocalizedCategory` helpers provide clean fallback to base fields when a translation for a specific locale is not present.

### Translation process

1. Create the original content.
2. Prepare the second-language version.
3. Review important details.
4. Publish the approved version.
5. Record when it was last reviewed.

Automated translation may assist with drafts, but emergency, healthcare, immigration, payment, and legal information must receive human review before publication.

## 7.3 Translation fallback

If a translation is unavailable:

1. Display the available original language.
2. Do not show an empty description.
3. Avoid silently translating critical information without review.

# 8. Content Management Workflow

Every content item should follow a defined publishing process.

<escape>Draft → Review → Approved → Published → Updated or Archived</escape>

### Draft

Content is being created or information is being collected.

### Review

Check accuracy, spelling, images, links, and translations.

### Approved

Content is ready for publication.

### Published

Content is publicly visible.

### Updated or Archived

Content has changed, expired, or is no longer relevant.

### Suggested content statuses

- Draft.
- Pending Review.
- Approved.
- Published.
- Archived.

Only authorised users should change publication status.

# 12. Content and Database Relationship

Content should use the existing Supabase schema where possible.

Recommended content entities:

- Categories.
- Businesses.
- Business tags.
- Events.
- Accommodation enquiries.
- Essential services.
- Articles.
- Translation records, if using a separate translation model.

Avoid creating separate tables for every small content variation.

Use structured fields for information that needs filtering, sorting, or validation. Use rich text only for editorial descriptions.

| Metric                | What it indicates              |
| --------------------- | ------------------------------ |
| Category views        | Interest in a content category |

| Contact clicks        | Potential customer interest    |
| Event views           | Community discovery            |

Nomads Pipa should be a curated local knowledge platform.

- Accurate.
